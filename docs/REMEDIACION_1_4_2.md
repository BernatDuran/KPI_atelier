## Contratos que conviene conocer

El objetivo se configura en la tarjeta y es compartido. Comparaciones y progreso duplicados usan el valor de `value_copyN` cuando está disponible; en caso contrario, el principal. Las copias de valor, tendencia, referencia y estado conservan las medidas que admite cada elemento. Los calendarios particulares, medidas antiguas de elementos asociados y objetivos particulares que ya no forman parte del contrato se explican al cargar. Los controles que ofrecían valores descartados se sustituyen por información de su fuente efectiva.

La biblioteca conserva las entradas originales de diseños que no se han editado. Los avisos de normalización y la revisión raw son metadatos transitorios: no se añaden al registro guardado. Al guardar una versión revisada, su configuración pasa al contrato actual. El guardado seguro de diseños nombrados y paletas requiere Web Locks; cuando no están disponibles, se conserva la edición y se informa del fallo.

- `npm run check`: correcto; incluye tipos, **222/222** pruebas Node y **41/41** pruebas de escritorio Edge.

- Motor Power BI Desktop: **44/44** consultas correctas, con tablas y medidas `DEFINE` acotadas a cada consulta. No se ejecuta `SaveChanges` ni se crean medidas persistentes. El registro de resultados y hash de cada consulta está en [VALIDACION_DAX_1_4_2.json](VALIDACION_DAX_1_4_2.json); coincide con las consultas generadas por las fuentes finales.
- Distribución: carpeta, inventario completo, versión, hashes y ZIP extraído verificados mediante los scripts de release. El sidecar identifica los bytes concretos del ZIP.

Las consultas reales comprueban cálculo y HTML generado con datos de prueba; la visualización final dentro de HTML Content Secure y las relaciones de cada informe requieren comprobación en ese entorno. La vista previa sigue utilizando muestras. El extractor TMDL obtiene metadatos y no pretende sustituir al compilador completo. No se ha realizado una certificación integral con lectores de pantalla.

Los borradores continúan siendo independientes por ventana y se persisten de forma síncrona; no se ha introducido un motor transaccional nuevo para ellos. Diseños nombrados y paletas sí coordinan todas sus mutaciones entre ventanas. No se añade sincronización entre equipos.
